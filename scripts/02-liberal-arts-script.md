# 발표 스크립트: 학부대학 출범과 기초교양 강화 전략

> 아래는 20분 PT를 실제 발표하듯 작성한 구어체 스크립트입니다.

---

## 도입 (2분)

안녕하십니까. 서울대학교 정보화본부 전산직에 지원한 ○○○입니다.

오늘 발표 주제는 **"학부대학 출범과 기초교양 강화, 그리고 정보시스템의 역할"**입니다.

대학 교육의 패러다임이 바뀌고 있습니다. 전공 조기 선택보다는 1~2학년 동안 폭넓은 기초교양을 다진 후 전공을 결정하는 학부대학 모델이 주목받고 있습니다. 하버드, 예일 같은 대학은 이미 오래전부터 이 체제를 운영하고 있고, 국내에서도 연세대가 학부대학을 운영하고 있습니다.

서울대 역시 자유전공학부를 넘어 보다 포괄적인 학부대학 체제를 검토하고 있다고 알고 있습니다. 그런데 전체 1학년 약 3,000명을 공통 교육과정으로 운영한다는 것은, 수강신청부터 분반 배정, 성적관리, LMS 운영까지 시스템 전반에 큰 변화를 요구합니다.

이 변화를 정보시스템 관점에서 어떻게 뒷받침할 수 있는지 말씀드리겠습니다.

---

## 현황 분석 (5분)

먼저 국내외 사례를 살펴보겠습니다.

연세대 학부대학은 신입생 전원을 1년간 공통 교육과정으로 운영하며, 자체 LMS와 학사시스템을 연동하고 있습니다. 하버드의 경우 학부생 전원이 교양 과목을 이수하며, AI 기반 수강 추천 시스템을 도입해 학생별 맞춤 교과과정을 안내하고 있습니다.

서울대 현황을 보면, 기초교육원에서 교양 교과를 관리하고 있지만, 수강신청 시스템은 전공과 교양을 구분 없이 같은 파이프라인으로 처리합니다. 매 학기 수강신청 기간에 서버 부하가 집중되는 것은 이미 잘 알려진 문제입니다.

현행 LMS인 eTL과 학사시스템(SAP) 사이의 데이터 연동도 실시간이 아닙니다. 교수가 eTL에 성적을 입력하고, 다시 SAP에 별도로 입력하는 이중 작업이 발생합니다. 학습 활동 데이터(출석, 과제 제출, 퀴즈 점수)도 eTL 안에 머물러 있어서, 학생의 학습 성과를 종합적으로 분석하는 것이 어렵습니다.

분반 배정도 살펴볼 필요가 있습니다. 3,000명이 동일한 교양 과목을 듣는다면, 수십 개 분반이 필요하고, 시간·강의실·교수 배정이 복잡한 최적화 문제가 됩니다. 현재는 대부분 수작업에 가까운 방식으로 처리되고 있습니다.

---

## 문제 진단 (4분)

핵심 문제를 세 가지로 정리했습니다.

**첫째, 대규모 공통교과 분반 배정의 비효율입니다.** 학부대학이 출범하면 필수 교양 과목의 분반 수가 크게 늘어납니다. 수강 인원, 시간표, 강의실 수용 인원, 교수 가용 시간을 모두 고려한 최적 배정이 필요한데, 이를 수작업으로 처리하면 배정 오류와 불만이 반복됩니다.

**둘째, 학습성과 추적 시스템의 부재입니다.** 기초교양 교육의 목표가 "역량 함양"이라면, 학생이 어떤 역량을 어느 수준까지 도달했는지 추적할 수 있어야 합니다. 그런데 현재는 과목별 성적 외에는 축적되는 데이터가 없습니다.

**셋째, LMS와 학사시스템 간 데이터 단절입니다.** eTL의 학습 활동 데이터와 SAP의 학사 데이터가 연결되지 않으면, 이중 입력이라는 실무적 불편뿐 아니라, 데이터 기반 교육과정 개선도 불가능합니다.

---

## 해결 방안 (7분)

네 가지 방안을 제안합니다.

**첫째, AI 기반 분반 최적 배정 알고리즘 도입입니다.**

수강 신청 데이터, 시간표, 강의실 정보, 교수 가용 시간을 입력값으로 받아 최적 분반을 자동 배정하는 알고리즘을 개발합니다. 이미 타 대학에서 OR(Operations Research) 기법을 활용한 사례가 있고, 서울대의 데이터 규모라면 충분히 적용 가능합니다.

학생의 선호 시간대, 이동 동선까지 반영하면 만족도도 높일 수 있습니다. 초기에는 알고리즘 결과를 담당자가 검토·보정하는 반자동 방식으로 시작하고, 신뢰도가 확보되면 점진적으로 자동화 비율을 높이면 됩니다.

**둘째, LMS-학사시스템 통합 API 구축입니다.**

eTL과 SAP 사이에 표준 API를 만들어서, 성적·출석·과제 데이터가 실시간으로 동기화되도록 합니다. 교수는 eTL에만 입력하면 되고, SAP에는 자동 반영됩니다. 이것만으로도 교원과 행정 담당자의 이중 업무를 크게 줄일 수 있습니다.

기술적으로는 REST API 기반 미들웨어를 구축하고, 데이터 변환·검증 로직을 두는 방식입니다. 보안 측면에서는 학생 개인정보가 오가므로, API 인증과 암호화가 반드시 수반되어야 합니다.

**셋째, 학습 대시보드 구축입니다.**

학생 개인이 자신의 학습 진행 상황을 한눈에 볼 수 있는 대시보드를 만듭니다. 과목별 성적뿐 아니라, 역량 달성도, 교양 이수 현황, 남은 졸업 요건 등을 시각적으로 제공합니다.

학과 담당자와 교학 부서에게는 집계된 형태의 대시보드를 제공하여, 교육과정 효과를 측정하고 개선점을 도출할 수 있게 합니다.

**넷째, 역량 포트폴리오 DB 설계입니다.**

교양 교육과정에서 목표로 하는 핵심 역량(비판적 사고, 의사소통, 데이터 리터러시 등)을 정의하고, 각 과목·활동과 역량의 매핑 관계를 DB로 관리합니다. 학생의 학습 기록이 쌓이면서 역량 프로필이 자연스럽게 형성되는 구조입니다.

이 데이터는 전공 선택 상담, 진로 안내, 졸업 후 취업 지원에도 활용할 수 있어서, 장기적으로 큰 가치를 갖습니다.

---

## 마무리 (2분)

정리하겠습니다.

학부대학 출범은 교육 철학의 전환이지만, 그 실행은 시스템이 담당합니다. 3,000명의 공통 교육과정을 효과적으로 운영하려면, 분반 배정 자동화, LMS-학사시스템 연동, 학습 대시보드, 역량 포트폴리오 DB가 필요합니다.

교양교육 혁신이 구호에 머물지 않고 실제로 작동하려면, 데이터와 시스템이 뒷받침되어야 합니다. 그리고 그 기반을 만드는 것이 정보화본부의 역할이라고 생각합니다.

감사합니다.
