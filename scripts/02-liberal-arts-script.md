# 발표 스크립트: 학부대학 출범과 기초교양 강화 전략

> 아래는 20분 PT를 실제 발표하듯 작성한 구어체 스크립트입니다.

---

## 도입 (2분)

안녕하십니까. 서울대학교 정보화본부 전산직에 지원한 ○○○입니다.

오늘 발표 주제는 **"학부대학 출범과 기초교양 강화, 그리고 정보시스템의 역할"**입니다.

대학 교육의 패러다임이 바뀌고 있습니다. 1~2학년 동안 폭넓은 기초교양을 다진 후 전공을 결정하는 학부대학 모델이 주목받고 있는데, 서울대는 이미 자유전공학부를 통해 이 방향을 선도해 왔습니다. 기초교육원 역시 교양 교육과정을 체계적으로 운영하며 그 기반을 꾸준히 다져왔습니다.

보다 포괄적인 학부대학 체제로 나아가는 논의가 이어지고 있는 지금, 전체 신입생이 공통 교육과정을 이수하는 구조는 수강신청부터 분반 배정, 성적관리, LMS 운영까지 시스템 전반에 새로운 요구를 더합니다.

오늘은 서울대가 이미 잘 구축해온 시스템 위에서, 이 변화를 어떻게 자연스럽게 수용해 나갈 수 있을지 말씀드리겠습니다.

---

## 현황 분석 (5분)

먼저 서울대가 지금 잘하고 있는 것들을 이야기하고 싶습니다.

eTL은 서울대가 오래 운영해온 LMS로, 이미 전교 수업의 과제 제출, 공지, 강의 자료 배포가 이 플랫폼을 중심으로 이루어지고 있습니다. 교수, 학생 모두에게 익숙한 환경이 구축되어 있다는 것은 큰 자산입니다. 새 시스템을 도입할 때 생기는 학습 비용과 저항이 없다는 뜻이기 때문입니다.

SAP 기반 학사시스템은 수만 명의 학생이 동시에 수강신청하는 상황에서도 안정적으로 동작합니다. 복잡한 이수 요건 계산, 졸업 판정, 성적 처리를 처리하는 이 시스템은 수십 년간 운영하며 다듬어온 결과물입니다.

기초교육원은 교양 교과를 오랜 기간 관리해왔고, 자유전공학부는 이미 기존 학부와 다른 이수 체계를 운영하며 유연한 학제를 선보여왔습니다.

하버드는 학부생 전원에 AI 기반 수강 추천 시스템을 도입했고, 연세대 학부대학은 신입생 전원을 공통 교육과정으로 운영하면서 자체 LMS와 학사시스템을 연동했습니다. 서울대는 그 기반이 이미 갖춰져 있습니다. eTL과 SAP라는 두 개의 축이 있고, 기초교육원과 자유전공학부라는 운영 경험도 있습니다.

다음 단계로 나아가기 위해 어떤 연결이 더해지면 좋을지, 그 부분을 말씀드리겠습니다.

---

## 한 걸음 더 (4분)

이미 잘 운영되는 플랫폼들이 있는 만큼, 이것들이 서로 더 잘 연결된다면 어떨까 하는 생각이 있습니다.

**첫째, eTL과 SAP 사이의 데이터 흐름입니다.** 현재 교수가 eTL에 성적을 입력하고, SAP에 다시 별도로 입력하는 이중 작업이 발생하는 경우가 있습니다. 두 시스템이 각각 잘 운영되고 있는 만큼, 이 사이를 잇는 연동이 강화된다면 교원과 행정 담당자의 실무 부담이 줄어들 것입니다. eTL의 학습 활동 데이터(출석, 과제 제출, 퀴즈 점수)도 현재는 eTL 안에 머물러 있어, 학생 학습 성과를 종합적으로 보기 어렵습니다.

**둘째, 대규모 공통교과 운영의 복잡도입니다.** 전체 신입생이 공통 필수 교양을 이수하는 구조가 되면, 수십 개 분반의 시간·강의실·교수 배정이 필요합니다. 지금의 방식으로도 처리는 가능하지만, 배정 과정이 더 체계적으로 지원된다면 운영 부담을 줄일 수 있습니다.

두 가지 모두, 지금 있는 것이 부족하다는 이야기가 아닙니다. 이미 잘 쌓아온 두 시스템 사이에 다리를 하나 더 놓는 것입니다.

---

## 제안 (7분)

이미 이런 기반이 있으니, 여기에 한 가지씩 더하면 어떨까 싶습니다.

**첫째, eTL-SAP 연동 API 확장입니다.**

eTL과 SAP 사이에 표준 API를 만들어, 성적·출석·과제 데이터가 한쪽에서 입력되면 다른 쪽에 자동으로 반영되도록 합니다. 교수는 eTL에만 입력하면 되고, SAP에는 자동 반영됩니다. 이것만으로도 교원과 행정 담당자의 이중 업무를 크게 줄일 수 있습니다.

기술적으로는 REST API 기반 미들웨어를 구축하고, 데이터 변환·검증 로직을 두는 방식입니다. 두 시스템 모두 이미 잘 운영되고 있으므로, 원본 시스템을 건드리는 것이 아니라 연결 레이어만 추가하는 것입니다. 개인정보가 오가는 만큼 API 인증과 암호화는 기본적으로 갖춰야 합니다.

**둘째, 학습 대시보드 추가입니다.**

eTL 안에 이미 쌓이는 학습 활동 데이터를 활용해, 학생이 자신의 학습 진행 상황을 한눈에 볼 수 있는 대시보드를 eTL 안에 더하는 것입니다. 새로운 플랫폼을 만드는 것이 아니라, 이미 있는 플랫폼의 기능을 확장하는 방향입니다.

과목별 성적뿐 아니라 역량 달성도, 교양 이수 현황, 남은 졸업 요건을 시각적으로 보여주면 학생들이 스스로 학습 경로를 점검하는 데 도움이 됩니다. 기초교육원이나 학과 담당자에게는 집계된 형태의 데이터를 제공하여 교육과정 효과를 살펴볼 수 있도록 하면, 교육과정 개선에도 이어집니다.

**분반 배정 지원에 대해서도** 한 가지 덧붙이자면, 수강 신청 데이터, 시간표, 강의실 정보를 활용해 최적 분반을 제안하는 보조 도구를 제공하는 방식이 있습니다. 최종 결정은 담당자가 하되, 시스템이 초안을 제안해주는 반자동 방식입니다. 지금 있는 데이터를 활용하는 것이므로 새로운 데이터 수집 부담도 없습니다.

---

## 마무리 (2분)

정리하겠습니다.

서울대는 eTL과 SAP이라는 검증된 두 플랫폼, 기초교육원의 운영 경험, 자유전공학부의 실험적 선례를 이미 갖고 있습니다. 학부대학 체제로의 확장은 이 기반 위에서 이루어지는 것이고, 그 전환이 부드럽게 이어지도록 정보시스템이 뒷받침하는 역할이 중요합니다.

저는 이미 잘 쌓아온 것들 위에서, 연결과 확장을 통해 기여하고 싶습니다. 새것을 만드는 것보다 있는 것을 잘 이어주는 일이 때로 더 값집니다.

감사합니다.
