# 5. DRT(수요응답형 교통)와 스마트캠퍼스 모빌리티

**한 줄 요약:** 캠퍼스 이동을 데이터로 최적화

**배경** (3줄 이내)
- 관악캠퍼스는 넓은 부지와 경사 지형으로 인해 교내 이동이 상당한 시간과 체력을 요구한다.
- 셔틀버스 고정 노선의 비효율과 이용 불편이 지속적으로 제기되고 있다.
- DRT(Demand Responsive Transit)는 실시간 수요에 맞춰 노선을 탄력적으로 운영하는 교통 모델이다.

**20분 PT 구조**

| 파트 | 시간 | 핵심 내용 (키워드 중심) |
|------|------|------------------------|
| 도입 | 2분 | 관악캠퍼스 이동 문제, DRT 개념 소개, 스마트 모빌리티 흐름 |
| 현황 분석 | 5분 | 현행 셔틀 운행 데이터, 이용자 불만 사항, 국내 DRT 도입 사례(세종시, 경기도) |
| 문제 진단 | 4분 | 고정 노선의 수요-공급 불일치, 배차 간격 비효율, 이동 데이터 수집 체계 부재 |
| 해결 방안 | 7분 | 캠퍼스 DRT 앱 개발(실시간 호출·배차), 이동 데이터 수집·분석 플랫폼, 전기 셔틀 도입, 단계적 시범 운영 계획 |
| 마무리 | 2분 | 모빌리티 혁신은 캠퍼스 생활의 질과 직결되며, 데이터 기반 운영의 좋은 시범 사례가 될 수 있다는 점 |

**핵심 논거 3가지**
1. 이동 패턴 데이터를 수집하면 수업 시간표 기반 수요 예측이 가능하고, 이를 통해 배차 최적화를 실현할 수 있다.
2. DRT는 고정 노선 대비 운영 비용을 절감하면서 이용자 만족도를 높이는 것이 입증된 모델이다.
3. 캠퍼스 DRT는 정보화본부의 앱 개발·데이터 분석 역량을 대외적으로 보여줄 수 있는 가시적 프로젝트다.

**서울대 정보화본부 미션 연결**
- **지능형캠퍼스**: IoT 센서·앱 기반 캠퍼스 모빌리티 시스템
- **데이터기반행정**: 이동 패턴 데이터 분석, 수요 예측 모델
- **정보서비스만족도**: 실시간 셔틀 정보, 편리한 호출 앱 UX

**예상 꼬리 질문 2가지**
- Q1: 관악캠퍼스 규모에서 DRT 운영이 경제적으로 타당한가? 비용 대비 효과를 어떻게 검증하겠는가?
- Q2: DRT 앱 개발·운영을 정보화본부가 직접 할 것인가, 외주할 것인가?
